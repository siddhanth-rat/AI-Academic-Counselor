## 💬 The Complete "Sending a Message" Lifecycle

When a user types a message and clicks send, here is exactly what happens step-by-step:

### 1. The Text Box (User Input)
- **File**: `src/app/(chat)/page.tsx`
- **Location**: Line ~527
- **What it does**: This is the literal HTML `<textarea>`. It binds its value to the React state variable `input`. When you type, `onChange={handleInput}` fires, updating the state.
```tsx
<textarea
  id="chat-input-textarea"
  value={input}
  onChange={handleInput}
  onKeyDown={handleKeyDown}
  disabled={isTyping}
  className="w-full resize-none overflow-hidden bg-transparent py-4 pl-12 pr-14..."
/>
```

### 2. The Send Button & Logic
- **File**: `src/app/(chat)/page.tsx`
- **Location**: Line ~202
- **What it does**: Clicking "Send" triggers `handleSend`. This function first checks if the user is trying to escalate to a human. Then it prepares the `userMessage` and calls the global React Context to update the UI instantly (optimistic UI rendering).
```tsx
const handleSend = async (text: string = input) => {
  if (!text.trim() || isTyping) return;
  
  // 1. Instantly show the user's message on the screen
  const userMessage: Message = { role: "user", content: text };
  updateActiveMessages((prev) => [...prev, userMessage, { role: "model", content: "", isLoading: true }]);
  
  // 2. Fetch the backend API stream
  const response = await fetch("/api/v1/chat/stream", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ 
       messages: [...messages, userMessage], // Sends the ENTIRE chat history
       sessionId: activeSession?.id 
    }),
  });
  
  // 3. Read the stream
  await readSSEStream(response);
}
```

### 3. Reading the Server-Sent Events (SSE) Stream
- **File**: `src/app/(chat)/page.tsx`
- **Location**: Line ~165
- **What it does**: The `readSSEStream` function continuously loops, reading chunks of text generated by the AI in real-time, and updating the UI instantly so you get a "typewriter" effect.
```tsx
const readSSEStream = async (response: Response) => {
  const reader = response.body.getReader();
  let aiResponse = "";
  
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    
    // Parses the data chunk
    const parsed = JSON.parse(data);
    if (parsed.text) {
      aiResponse += parsed.text; // Append the new text
      
      // Update the UI
      updateActiveMessages((prev) => {
        const msgs = [...prev];
        msgs[msgs.length - 1] = { role: "model", content: aiResponse, isLoading: false };
        return msgs;
      });
    }
  }
};
```

### 4. The Backend AI Generation (Gemini)
- **File**: `src/app/api/v1/chat/stream/route.ts`
- **Location**: Line ~326
- **What it does**: This receives the `POST` request. It calls Google's Gemini AI, passing the `SYSTEM_INSTRUCTION` (from `src/lib/AI_instructions.ts`) and the chat history.
```typescript
responseStream = await ai.models.generateContentStream({
  model: "gemini-2.5-flash",
  systemInstruction: SYSTEM_INSTRUCTION + "\n\n[RELEVANT KNOWLEDGE BASE CONTEXT]:\n" + context,
  contents: reqBody.messages.map((m: any) => ({
    role: m.role === "user" ? "user" : "model",
    parts: [{ text: m.content }]
  }))
});

// Stream the response back to the client chunk by chunk
for await (const chunk of responseStream) {
  const text = chunk.text();
  await sendSSE(JSON.stringify({ text }));
}
```

### 5. Saving to the Database (Prisma)
- **File**: `src/app/api/v1/chat/stream/route.ts`
- **Location**: Line ~413
- **What it does**: After the AI finishes streaming its response to the user, the server saves both the user's prompt and the AI's final response into PostgreSQL.
```typescript
await prisma.$transaction([
  prisma.message.createMany({
```

## 🤖 Retrieval-Augmented Generation (RAG) Flow

How does the AI search the knowledge base when you ask a question?

### 1. The Vector Search Query
- **File**: `src/lib/rag.ts`
- **Location**: Line ~36
- **What it does**: The `getRelevantContext` function takes the user's string prompt, turns it into a mathematical vector (Embedding) using Gemini `text-embedding-004`, and queries the Pinecone vector database.
```typescript
export async function getRelevantContext(query: string): Promise<string> {
  // 1. Turn the query into an embedding
  const embeddingRes = await ai.models.embedContent({
    model: "text-embedding-004",
    contents: query,
  });

  // 2. Search Pinecone for the Top 3 most relevant chunks
  const queryResponse = await index.query({
    vector: embeddingRes.embeddings[0].values,
    topK: 3,
    includeMetadata: true,
  });

  // 3. Combine the text from the top chunks
  return queryResponse.matches.map(m => m.metadata?.text).join("\n\n");
}
```

## 🔐 Authentication & Role-Based Access Control (RBAC)

How does the app know who is an Admin and who is a Student?

### 1. The NextAuth Configuration
- **File**: `src/auth.ts` and `src/app/api/auth/[...nextauth]/route.ts`
- **What it does**: When a user logs in, NextAuth checks their hashed password. If successful, the `jwt` callback embeds their database `id` and `role` directly into the JSON Web Token. The `session` callback then makes it available to the React frontend.
```typescript
callbacks: {
  async jwt({ token, user }) {
    if (user) {
      token.id = user.id;
      token.role = user.role; // e.g., "STUDENT" or "ADMIN"
    }
    return token;
  },
  async session({ session, token }) {
    if (token && session.user) {
      (session.user as any).id = token.id;
      (session.user as any).role = token.role;
    }
    return session;
  }
}
```

### 2. Frontend Role Blocking
- **File**: `src/components/StaffNavigation.tsx`
- **Location**: Line ~14
- **What it does**: The sidebar dynamically checks the `session.user.role`. If the user is an `ADMIN`, it injects the "Counselor Performances" link. If they are a student, they never even see the link.
```tsx
const { data: session } = useSession();
const role = (session?.user as any)?.role;

const links = [...baseLinks];
if (role === "ADMIN") {
  links.splice(2, 0, { href: "/dashboard/performances", label: "Counselor Performances", exact: true });
}
```

How is the mandatory Counselor Rating calculated?

### 2. The Moving Average Calculation
- **File**: `src/app/api/v1/chat/counselor-rating/route.ts`
- **What it does**: The backend looks up the counselor who handled the chat. It calculates the new `satisfaction_score` by factoring in the new rating against their total handled chats (a moving average).
```typescript
// Example of the moving average math:
const oldScore = Number(performanceRecord.satisfaction_score) || 0;
const totalHandled = performanceRecord.total_handled;

const newScore = ((oldScore * (totalHandled - 1)) + rating) / totalHandled;

await prisma.counselorPerformance.update({
  where: { counselor_id: sessionRecord.counselor_id },
  data: { satisfaction_score: newScore }
});
```
